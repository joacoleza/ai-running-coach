    DURATION VALIDATION (RunEntryForm):
    Replace the current loose regex `/^\d{1,2}:\d{2}(:\d{2})?$/` with a strict one:
    `/^\d{1,2}:\d{2}$|^\d{1,2}:\d{2}:\d{2}$/` — this explicitly requires exactly two digits
    for the seconds segment and allows the first segment to be 1 or 2 digits.
    The key insight: `\d{2}(:\d{2})?` matches "12:0011" because `\d{2}` matches "00" and the
    remaining "11" is ignored by the match (it only checks for a match, not full string match).
    The current regex is missing the `^` anchor effect on the end — add `$` end anchors.
    The correct strict regex: `/^(\d{1,2}):(\d{2})(:(\d{2}))?$/.test(duration)` — this requires
    the string to end after the optional HH:MM:SS group.
    Actually the simplest fix: change `duration.match(...)` to test the full pattern with `$`:
    `const durationValid = /^\d{1,2}:\d{2}$/.test(duration) || /^\d{1,3}:\d{2}:\d{2}$/.test(duration);`
    This allows 1-3 digit hours but enforces exactly 2-digit minutes AND 2-digit seconds with
    nothing after. This is the correct fix.
