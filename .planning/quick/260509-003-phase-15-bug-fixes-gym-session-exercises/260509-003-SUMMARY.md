## Bugs Fixed

### 1. Gym session form shows exercises before save
**RunEntryForm.tsx** — Added `exercises` state and inline `ExerciseForm` below the Session Type field when `isGym`. Added/removed exercises are tracked in a local array and included in `createRun` payload. ExerciseForm is rendered directly (not ExerciseList, which is designed for post-save API editing).

### 2. Unified Save button covers exercise changes
**ExerciseList.tsx** — Removed `handleDone` and the "Save exercises" button. Added `onExercisesChange: (exercises: Exercise[]) => void` prop called via `useEffect` on `localExercises`. The `onUpdate` prop is now optional and unused.

**RunDetailModal.tsx** — Added `pendingExercises` state initialized from `run.exercises ?? []`. `ExerciseList` now receives `onExercisesChange={setPendingExercises}`. `isDirty` check extended with `exercisesChanged` (JSON.stringify deep comparison). `handleSave` includes `exercises: pendingExercises` when `exercisesChanged` is true.

### 3. Duration validation rejects malformed strings
**RunEntryForm.tsx** — Replaced loose regex `/^\d{1,2}:\d{2}(:\d{2})?$/` with strict pair:
```
/^\d{1,2}:\d{2}$/.test(duration) || /^\d{1,3}:\d{2}:\d{2}$/.test(duration)
```
The old regex matched `"12:0011"` because `\d{2}` matched `"00"` and the remaining `"11"` was not anchored. The new form requires the string to end exactly after the seconds group.

### 4. Link modal gym sessions show discipline-appropriate info
**LinkRunModal.tsx** — Added three-branch display in the list item render:
- Gym: `date · type · duration` (e.g. "Wednesday 01/04/2026 · Upper Body · 45:30")
- Cycle: `date · Xkm · speed`
- Run: `date · Xkm · pace`
Search filter extended to include `run.type` and `run.duration` for gym sessions.

### 5. "Log a session" label updated
**Runs.tsx** — Button label and modal h2 both changed from "Log a run" to "Log a session". **Runs.test.tsx** updated to match.
