## Interaction Contracts

### Discipline Selection (DISC-03)
- **Trigger:** User opens RunEntryForm
- **Visible by default:** "Run" discipline pre-selected
- **Options:** Run, Gym, Cycling (all three available, even though Cycling UI is Phase 15)
- **Field visibility behavior:**
  - **Run (default):** Show distance, hide type, show duration, show HR, show notes
  - **Gym:** Hide distance, show type (dropdown: upper/lower/full/other), show duration, show HR, show notes
  - **Cycle:** Show distance, hide type, show duration, show HR, show notes
- **Validation:** Only validate fields currently visible. Distance required for Run, Type required for Gym. Duration + Date always required.
- **Class pattern:** Use JSX conditional rendering `{discipline === 'gym' && <TypeSelect ... />}` NOT `display: none`
- **Mobile behavior:** Discipline selector dropdown remains accessible on all screen sizes (no hiding on mobile)

### Exercise Entry (GYM-02)
- **Trigger:** User completes a gym session form and clicks "Save Session"
- **UX flow (recommended):** 
  1. Run saved via `POST /api/runs`
  2. RunDetailModal opens showing logged session
  3. "Add Exercise" button/section appears in the modal
  4. User clicks to expand exercise entry form (inline, not modal-in-modal)
  5. User fills name, sets, reps, weight (weight optional)
  6. User clicks "Save Exercise" — appends to local `exercises[]` array in modal state
  7. User can add more exercises or click "Done" to close form
  8. On "Done" or navigation away, modal calls `PATCH /api/runs/:id` with final `exercises` array
- **Form validation:** 
  - Name: required, max 100 chars
  - Sets: required, integer ≥ 1, max 2 digits
  - Reps: required, integer ≥ 1, max 2 digits
  - Weight: optional; if provided, must be number > 0
  - Unit: optional if weight absent; required if weight present
- **Error display:** Inline below each field, red text (text-red-600), text-xs
- **Deduplication:** Warn user if they attempt to add exercise with same name twice: "You've already added [Name]. Do you want to add another instance?"
- **Limit:** Max 20 exercises per session (soft limit at 15 exercises, show warning banner)

### Exercise Display on Gym Plan Day (GYM-03, GYM-04)
- **Location:** PlanView, in DayRow component for gym days
- **Rendering:** 
  - Day label + guidelines display as usual
  - Below guidelines, add collapsible section: "Exercises (N)" where N = count
  - Initially collapsed on narrow screens, expanded on desktop (optional, TBD)
  - Expand/collapse trigger: Clickable chevron + text
- **Exercise list item layout:**
  - Checkbox (left) + exercise name + sets/reps/weight (right)
  - Example: `☐ Bench Press  3x8 @ 185lbs`
  - Alignment: Checkbox left-aligned, weight right-aligned, name flex-grow between
  - Spacing: 8px (sm) between items
- **Checkbox behavior:**
  - Clicking checkbox sets `exercise.completed = true` (visual feedback: greyed out or strikethrough)
  - Right-click or long-press (mobile) shows context menu: "Skip" option
  - Clicking "Skip" sets `exercise.skipped = true` (visual feedback: lighter color, strikethrough)
  - Unchecking reverts both flags to false
  - **Important:** Checking exercise does NOT mark plan day complete. Completion happens only when a run is logged and linked.
- **PATCH behavior:** On checkbox change, call `PATCH /api/plan/days/:week/:day` with updated `exercises[N].completed` or `.skipped` value. Handle optimistic UI update (immediate visual change, then API confirm).
- **Linked run integration (Phase 14 scope — TBD):** If a run is already linked to this day, show which exercises from the linked run matched plan targets (no auto-sync; user responsibility).

### Discipline Badge on Runs List (DISC-04)
- **Location:** Runs page, next to each session name/date in RunRow
- **Component:** New `<RunBadge discipline="gym" />` component
- **Visual style:**
  - Inline badge with emoji icon + text label
  - Pattern: `🏃 Run` / `💪 Gym` / `🚴 Cycling`
  - Background colors: blue-100/orange-100/green-100
  - Text colors: blue-700/orange-700/green-700
  - Padding: px-2 py-1 (8px horizontal, 4px vertical)
  - Border radius: rounded-full
  - Font size: text-xs, font-medium
  - Default (run with no discipline field): Badge shows "Run" (backward compatibility)
- **Placement:** Immediately after session date, before delete button (if space allows on mobile, adjust layout)
- **Tooltip (optional):** Hover shows full discipline name ("Running", "Strength Training", "Cycling")

### Discipline Filter on Runs Page (DISC-05)
- **Location:** Runs page header, above session list
- **UI pattern:** Tab bar or dropdown (TBD in planner; recommend tabs for visibility)
- **Tab options:** "All" (default), "Runs", "Gym", "Cycling"
- **Active state:** Bold text, blue-600 color (or background highlight)
- **Inactive state:** text-gray-600, hover:text-gray-900
- **Behavior:**
  - Clicking a tab updates local state and URL query param: `?discipline=gym` (enables sharing/bookmarking)
  - API query includes `?discipline=gym` if tab != "All"
  - Re-fetch runs list with filter applied
  - Persist filter to localStorage so filter survives page reload
- **Mobile behavior:** Tabs stack vertically or remain horizontal with scroll if needed (no collapsing into dropdown)

## Form Field Validation Rules

### Discipline Selector
- **Required:** Yes (always visible)
- **Default:** "Run"
- **Validation:** None (always valid)

### Date (all disciplines)
- **Required:** Yes
- **Format:** YYYY-MM-DD
- **Validation:** Must be valid date, ≤ today, ≥ 2000-01-01
- **Error:** "Please enter a valid date (not in the future)"

### Distance (Run + Cycle disciplines)
- **Required:** Yes for Run/Cycle; hidden for Gym
- **Format:** Decimal number (km)
- **Validation:** Must be > 0, max 3 digits + 1 decimal
- **Error:** "Distance required for {Discipline} sessions"

### Session Type (Gym discipline only)
- **Required:** Yes for Gym; hidden for Run/Cycle
- **Options:** "Upper Body", "Lower Body", "Full Body", "Other"
- **Default:** None (user must select)
- **Error:** "Please select a session type"

### Duration (all disciplines)
- **Required:** Yes
- **Format:** MM:SS or HH:MM:SS
- **Validation:** Must match regex `/^\d{1,2}:\d{2}(:\d{2})?$/`
- **Error:** "Duration required (format: MM:SS or HH:MM:SS)"

### Avg HR (all disciplines)
- **Required:** No
- **Format:** Integer (bpm)
- **Validation:** If provided, must be 30–220 (reasonable HR range)
- **Error:** "Average HR must be between 30 and 220"

### Notes (all disciplines)
- **Required:** No
- **Format:** Free text
- **Max length:** 500 chars
- **Validation:** None (accept any text)
- **Error:** None

### Exercise Name
- **Required:** Yes
- **Format:** Free text
- **Max length:** 100 chars
- **Validation:** Non-empty
- **Error:** "Exercise name is required"

### Sets
- **Required:** Yes
- **Format:** Integer
- **Validation:** > 0, ≤ 99
- **Error:** "Sets must be a whole number greater than 0"

### Reps
- **Required:** Yes
- **Format:** Integer
- **Validation:** > 0, ≤ 99
- **Error:** "Reps must be a whole number greater than 0"

### Weight
- **Required:** No (for body-weight exercises)
- **Format:** Decimal number (lbs or kg)
- **Validation:** If provided, must be > 0
- **Error:** "Weight must be greater than 0"

### Weight Unit
- **Required:** Only if weight provided
- **Options:** "lbs", "kg"
- **Default:** None (user selects)
- **Error:** "Please select a unit for weight"

## Design Notes

### Backward Compatibility
- Runs without `discipline` field will default to "Run" in UI (badge shows "Run" if field absent)
- Existing fixtures and legacy runs continue to work without migration

### Mobile Considerations
- All form fields use 16px font on mobile to prevent iOS zoom-on-focus
- Discipline selector and tabs remain visible on mobile (no collapsing to hamburger)
- Exercise list items stack vertically on mobile; ensure touchable checkbox target is ≥44px

### Accessibility
- Form labels linked to inputs via `<label htmlFor>` pattern
- Checkboxes use native `<input type="checkbox">` (not custom elements)
- Error messages in red text + aria-live region for dynamic updates
- Discipline badge includes text label (not icon-only) for clarity
- Filter tabs include visual active state (bold + color) + aria-current="page"

### Performance
- Discipline filter stored in URL query param (enables browser back button, shareable links)
- Exercise list cached in RunDetailModal state until user clicks "Done"
- PATCH /api/plan/days called once per exercise checkbox change (optimistic UI update)
- No bulk exercises export/import in Phase 14 (future consideration)
