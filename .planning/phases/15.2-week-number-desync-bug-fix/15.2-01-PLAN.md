<objective>
Fix the week-number desync bug: when `deleteLastWeekOfPhase` or `addWeekToPhase` calls `assignPlanStructure` to renumber plan weeks, the `runs` collection is not updated. Runs store `weekNumber` to link back to their plan day — after renumbering, they point to the wrong week, producing ghost-completed weeks and orphaned run links.

Purpose: Maintain referential integrity between the plan's week numbers and run documents. Without this fix, adding or deleting weeks corrupts the plan-run link state silently.

Output: Two patched handlers in `planPhases.ts` + unit tests confirming correct `weekNumber` propagation to runs.
</objective>

**Understanding the shift logic:**

For `addWeekToPhase`:
- The new week is appended to the END of the specified phase.
- `assignPlanStructure` then renumbers ALL weeks globally. The new week's number equals the last week of phase `phaseIndex` in the old numbering + 1. All weeks in subsequent phases shift up by 1.
- Shift rule: any run with `weekNumber >= newWeekNumber` gets `weekNumber += 1`.
- `newWeekNumber` = the week number assigned to the newly inserted week by `assignPlanStructure`.

For `deleteLastWeekOfPhase`:
- The last week of phase `phaseIndex` is removed (guard already ensures it has no non-rest days, so no runs are linked to it).
- `assignPlanStructure` renumbers. The deleted week's old number = `deletedWeekNumber`. All subsequent weeks shift down by 1.
- Shift rule: any run with `weekNumber > deletedWeekNumber` gets `weekNumber -= 1`.

**Implementation — addWeekToPhase handler** (after computing `recomputed` and before the `findOneAndUpdate`):

```typescript
// Determine which weekNumber was assigned to the newly inserted week.
// The new week is last in phase phaseIndex after map+append.
const newWeekNumber = recomputed[phaseIndex].weeks[recomputed[phaseIndex].weeks.length - 1].weekNumber;

// Bulk-shift runs: any run linked to this plan with weekNumber >= newWeekNumber gets +1.
// Use planId from plan._id to scope the update to this user's plan only.
await db.collection<Run>('runs').updateMany(
  { planId: plan._id, weekNumber: { $gte: newWeekNumber } },
  { $inc: { weekNumber: 1 } }
);
```

Place this BEFORE the `findOneAndUpdate` call (so if the plan update fails, the runs update is the only inconsistency — the plan guard prevents a deleted-week from having runs, so this order is safe).

**Implementation — deleteLastWeekOfPhase handler** (after computing `recomputed` and before the `findOneAndUpdate`):

// The deleted week's number — captured from plan BEFORE reassignment.

  { planId: plan._id, weekNumber: { $gt: deletedWeekNumber } },
  { $inc: { weekNumber: -1 } }

Place this BEFORE the `findOneAndUpdate` call.

  it('increments weekNumber on runs whose weekNumber >= newly inserted week number', async () => {
    const db = mongoClient.db('running-coach');

    const runOnWeek2 = await db.collection('runs').insertOne({
      planId: PLAN_OID,

    await db.collection('runs').insertOne({
      planId: PLAN_OID,
      weekNumber: 1,
      dayLabel: 'A',
      date: '2026-01-01',
      distance: 5,
      duration: '30:00',
      pace: 6,
      userId: TEST_USER_OID,
      createdAt: new Date(),
      updatedAt: new Date(),
