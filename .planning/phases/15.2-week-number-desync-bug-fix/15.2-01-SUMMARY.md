**MongoDB updateMany bulk-shifts runs.weekNumber in addWeekToPhase and deleteLastWeekOfPhase to prevent ghost-completed weeks and orphaned run links after plan restructuring**

## Accomplishments

- Fixed referential integrity bug: runs.weekNumber is now updated atomically when weeks are added or deleted from a plan phase
- addWeekToPhase: bulk-increments all runs with weekNumber >= newWeekNumber by +1 before updating the plan document
- deleteLastWeekOfPhase: bulk-decrements all runs with weekNumber > deletedWeekNumber by -1 before updating the plan document

## Decisions Made

- `updateMany` runs before `findOneAndUpdate` plan — if the plan update fails, the run shift already occurred, but this is acceptable because the guard ensuring no non-rest days on the deleted week prevents orphaned run links from existing
- Scoped `updateMany` by `planId` (the plan's ObjectId) rather than `userId` — one plan per user, and planId provides tighter targeting
- `addWeekToPhase` uses `{ $gte: newWeekNumber }` — the new week occupies the slot previously held by phase1's first week, so runs at that exact week number must shift
- `deleteLastWeekOfPhase` uses `{ $gt: deletedWeekNumber }` — the deleted week had no runs (guard), so exclusive comparison is correct
