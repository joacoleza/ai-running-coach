# Phase 15.1: Multi-Discipline UI Polish - Context

**Gathered:** 2026-05-07
**Status:** Ready for planning
**Source:** User-reported issues after Phase 15 completion

<domain>
## Phase Boundary

Fix all places in the UI where "run"-specific labels, fields, and actions are shown for gym or cycling sessions without discipline awareness. This is pure frontend polish — no new API endpoints, no data model changes, no backend work.

Files in scope:
- `web/src/components/layout/Sidebar.tsx`
- `web/src/components/runs/RunDetailModal.tsx`
- `web/src/components/runs/ExerciseList.tsx`
- `web/src/components/runs/ExerciseForm.tsx`
- `web/src/components/runs/LinkRunModal.tsx`
- `web/src/components/runs/RunEntryForm.tsx` (add defaultDiscipline prop)
- `web/src/components/plan/DayRow.tsx`
- `web/src/hooks/useRuns.ts` (add discipline param to fetchUnlinkedRuns)

</domain>

<decisions>
## Implementation Decisions

### Sidebar rename
- `Sidebar.tsx` navItems: change `label: "Runs"` to `label: "Activities"`, keep the same path `/runs`
- Icon: change from `🏃` to `🏋️` (or keep 🏃 — user didn't specify icon, change label only is sufficient)

### RunDetailModal — gym sessions
- Hide the Distance field (the entire grid cell) when `run.discipline === 'gym'`
- Hide the Pace/Speed field (the entire grid cell) when `run.discipline === 'gym'`
- Show `RunBadge` component in the modal header, next to the date title
- "Add feedback to run" button → label becomes `'Get coaching feedback'` for ALL disciplines (universally better label, avoid discipline branching on button text)
- "Delete run" (disabled, when linked) → `'Delete session'`
- "Delete run" (active, when unlinked) → `'Delete session'`
- `handleAddFeedback` for gym sessions: the current code references `distStr` and `paceStr` even for gym. Fix: for gym sessions construct a different message — no distance/pace lines, include session type and exercises count instead:
  ```
  Please give me coaching feedback on my gym session:
  Date: {dateStr}
  Type: {run.type ?? 'General'}
  Duration: {run.duration}
  Exercises: {run.exercises?.length ?? 0} logged
  {notesStr}
  {planStr}
  ```

### ExerciseList / ExerciseForm UX
- ExerciseForm "Save Exercise" button label → `'Add'` (it only adds to local list, not the DB)
- ExerciseList "Done" button label → `'Save exercises'`
- ExerciseList layout: add `mt-4 pt-3 border-t border-gray-100` above the "Save exercises" button to visually separate it from the exercise list and "+ Add Exercise" link

### DayRow — discipline-aware labels and indicator
- Add a discipline badge/pill inline with the day label. Reuse `RunBadge` import or inline a small helper. Show only when `day.discipline && day.discipline !== 'run'` (run is the implicit default, no need to badge it unless we want to badge all disciplines — badge all for clarity). Actually, badge ALL disciplines for clarity.
- "Log run" buttons (two occurrences in DayRow): change to `'Log session'`  
- "Link run" button: change to `'Link session'`
- Modal title `"Log a run"` → `"Log session"`
- DayRow modal for logging: pass `defaultDiscipline={day.discipline ?? 'run'}` to `RunEntryForm` so the form pre-selects the correct discipline
- `RunEntryForm` needs a `defaultDiscipline?: 'run' | 'gym' | 'cycle'` prop; initialize `const [discipline, setDiscipline] = useState<Discipline>(defaultDiscipline ?? 'run')`

### LinkRunModal — filter by discipline
- Add `dayDiscipline?: string` prop to `LinkRunModal`
- `fetchUnlinkedRuns` in `useRuns.ts`: add optional `discipline?: string` param; when provided append `&discipline=${discipline}` to the query string
- `LinkRunModal` passes `dayDiscipline` to `fetchUnlinkedRuns` so only matching sessions appear
- `PlanView.tsx` passes `dayDiscipline={day.discipline}` in the `linkingDay` state object (add `discipline` field to the state type) and forwards it to `LinkRunModal`
- LinkRunModal header text: "Link a session to Week N Day X" (was "Link a run to...")
- Empty state message when no unlinked sessions found: "No unlinked {discipline} sessions available. Log one from the Activities page first." (was "No unlinked runs available...")

### Claude's Discretion
- Test file updates — update Sidebar.test.tsx to expect "Activities" label; update LinkRunModal.test.tsx if discipline prop is added
- Whether to badge ALL disciplines in DayRow or only non-run ones — badge all for consistency

</decisions>
